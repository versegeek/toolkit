# toolkit

Ready-made building blocks for Go services, and the machinery that initialises, runs and closes them in order.

## Language

### Building blocks

**Provider**:
A component that owns one external resource or service, such as a database pool, a Redis client or an HTTP server, and can be initialised and closed.
_Avoid_: plugin, module, component, service

**Run provider**:
A provider that also works in the foreground until it is stopped, such as serving HTTP or gRPC.
_Avoid_: server provider, runner, daemon

**Enabled**:
Whether configuration switches a provider on; a disabled provider is skipped entirely.
_Avoid_: active, on

**Provider set**:
The bundle of constructors a provider package exposes for Wire.
_Avoid_: wire set, module

### Lifecycle

**Init**:
The step that opens a provider's connections or prepares its resources.
_Avoid_: start, open, setup

**Run**:
The blocking step of a run provider, entered only after every provider has been initialised.
_Avoid_: start, serve, launch

**Close**:
The step that releases a provider's resources; for a run provider it also makes Run return.
_Avoid_: stop, shutdown, teardown

**Cleanup**:
The function handed back with an initialised provider, or with everything an injector built, that closes it.
_Avoid_: closer, finalizer, teardown

**Lifecycle**:
The ordered sequence Init, Run, Close applied to a set of providers, closing in reverse order of initialisation.
_Avoid_: stack, container, kernel

### Composition

**Group**:
A hand-assembled set of providers whose lifecycle is managed together.
_Avoid_: stack, container, app

**Injector**:
The application function, generated by Wire, that builds and initialises providers and returns them with one cleanup.
_Avoid_: container, factory

**Manual composition**:
Assembling providers by adding them to a group in code.
_Avoid_: Pattern A

**Wire composition**:
Assembling providers with an injector and handing its run providers and cleanup to the lifecycle.
_Avoid_: Pattern B
